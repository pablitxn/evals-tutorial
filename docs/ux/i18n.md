# English and Spanish presentation

`apps/web/src/i18n-core.ts` provides validated locale selection, English fallback,
plain-text interpolation and a presentation-only lesson overlay. `i18n.tsx` owns
React context, document language/title, cross-tab preference updates and the
accessible language dropdown in Preferences. No added localization framework is needed.

The independent `evals-tutorial:locale` localStorage key stores a JSON locale and
survives tutorial resets. Supported browser languages are considered in preference
order when no valid saved choice exists. Denied/full storage retains in-memory
selection and displays a localized notice after an explicit change. The provider
wraps the existing App; switching never changes component keys, lesson selection,
work/source/progress state, snapshots, pending submissions or API polling dependencies.

UI catalogs use English source strings as keys. Add both en/es entries and keep
interpolation parameter names identical. Parameter values render as React text,
never HTML. Unknown keys return the English source string. Avoid translating
identifiers, URLs, paths, actual diagnostics or executable snippets. Lesson overlays
cover all seven exercises and exact criterion IDs and require matching exercise
and rubric versions. Update translations when authoring new versions; unmatched
versions fall back to the original English content. Official documentation URLs,
tax-form names, units, amounts, status identifiers in JSON and ground truth stay
unchanged. Stored result explanations and fixture rationale remain raw evidence.

Review language is the narrow optional metadata addition documented in
`docs/contracts/v1.md`. It affects trusted prose instructions and fallibility notice
only. UI explains requested language, retained original feedback and explicit paid
retry; it never claims the model's language was verified.

Run `npm test`, `npm run contracts:check`, `npm run typecheck` and `npm run build`.
The root suite discovers catalog, locale, SSR rendering and review regressions.
`apps/web/tests/browser-test.py` checks production UI language switching, retention,
zero-POST switching, refresh, actual seven-lesson translations and narrow Spanish
layouts. It requires a running Vite preview and sandboxed Chromium; a launch failure
records an unverified gate. Static rendering tests cannot establish visual layout,
keyboard interaction or browser state retention. No insecure browser fallback is allowed.

The rehearsal uses Preferences and its language menu, CodeMirror keyboard input,
and the public evaluator copy action to verify exact source bytes. Its API routes
are synthetic; it never invokes the configured backend or provider. Start the
production preview on `127.0.0.1:4173` after building. Run the script with a Python
3.12 environment that already has Playwright, and Node 24 on `PATH`.
`TUTORIAL_BROWSER_EXECUTABLE` may select an installed Chromium/Chrome binary
(default `/usr/bin/chromium`); sandboxing remains required. Artifacts default to
the system temporary directory under `evals-tutorial-browser-evidence`.
`TUTORIAL_BROWSER_ARTIFACTS` can choose another directory outside the repository.
